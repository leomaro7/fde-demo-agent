## カテゴリ別の判断マトリクス

| カテゴリ | 承認後のデフォルト対応 |
|---|---|
| `SECRET`（実在のクレデンシャル） | 値を削除し、環境変数参照またはプレースホルダに置換し、**かつクレデンシャルをローテーションする**。下記参照。 |
| `SECRET`（誤検出。例：サンプル値） | reject（容認）として扱い、変更しない。値をより厳密にするか、プレースホルダ形式の採用を検討する。 |
| `PII`（email/phone/IP/カード） | 汎用プレースホルダ（`user@example.com`、`000-0000-0000`、`203.0.113.10`、`4111...`）に置換する。テストフィクスチャでは予約済み/ドキュメント用レンジを優先する。 |
| `NAME`（グロッサリまたは LLM 提案） | グロッサリの `REPLACEMENT`、または人間と決めた中立的な汎用語に置換する。新たに確定した名前は `.scrub-glossary` に追加する。 |

## 実在のシークレット：ローテーションは必須

漏れたクレデンシャルをテキスト置換しても安全には**ならない** — それを見た者（過去のローカル `commit`、ターミナル履歴、バックアップを含む）は依然として使える。

実在のシークレットが確定したら、人間に明示的に伝える：

1. クレデンシャルを発行元（クラウドコンソール、トークン設定）で**ローテーション/失効**させる。
2. ファイル内の値を環境変数参照（`API_KEY=${API_KEY}`）または文書化されたプレースホルダに置換する。
3. 実在の値を、git 管理外のシークレットストア / `.env` ファイルに移す。
4. `.gitignore` がそのシークレットを含むファイルをカバーしていることを確認する。

人間がローテーション完了、または意図的な保留を確認するまで `commit` に進まない。

## シークレットが既にローカルで `commit` 済みの場合

スキャナーは `git add` の**前**に走るので、目標はシークレットをそもそも `commit` に入れないこと。
ただし、まだ `push` されていない過去のローカル `commit` に既に含まれている場合、テキスト置換では履歴に残る。優先順の選択肢：

- `commit` を**まだ `push` していない**場合：ローカル履歴を書き換える（`git rebase`、またはリーク前まで `git reset --soft` で戻してクリーンに `commit` し直す）。
- いずれにせよ：**シークレットをローテーションする** — 履歴の書き換えだけでは不十分。
- 既に `push` 済みの場合：直ちにローテーションし、開示済みのシークレットとして扱う。

履歴の書き換えは破壊的 — 必ず人間に確認し、明示的な承認なしに force-push しない。

## 置換の規約

フィクスチャを現実的かつ安全に保つため、よく知られた予約済み/ドキュメント用の値を優先する：

- Email：`user@example.com`（RFC 2606 予約ドメイン）
- IPv4：`192.0.2.x`、`198.51.100.x`、`203.0.113.x`（RFC 5737 ドキュメント用レンジ）
- 電話（JP）：`03-0000-0000`、（US/intl）`+1-555-0100`
- クレジットカード：`4111 1111 1111 1111` は公知のテスト番号（テストでは許容）
- 設定内のシークレット：`${VAR_NAME}`（環境変数参照）

## 誤検出のチューニング

スキャナーは過剰報告寄りに振っており、human review でノイズを reject できるようにしてある。

- **プレースホルダ値**（`xxxx`、`<token>`、`${VAR}`、`changeme`、`example`）は、汎用の `key = value` ルールで既にフィルタ済み。
- **phone** と **IP** の検出器が最もノイズが多い。リポジトリに電話番号のように見えるバージョン番号や ID が多い場合、誤検出を見込む。パターンを全体的に弱めるのではなく review で reject する。
- 正当な文字列が繰り返し検出されるのを止める最もクリーンな方法は、ルールを無効化するのではなく、その値を明らかなプレースホルダにすること。

## gitleaks のインストール（任意）

スキャナーは gitleaks なしでも動作する（正規表現のフォールバック）。
インストールするとシークレットの網羅性が上がる。クロスプラットフォームのインストール：

- macOS：`brew install gitleaks`
- Windows：`winget install gitleaks` または `choco install gitleaks`
- 任意の OS：gitleaks の GitHub releases ページからリリースバイナリをダウンロードし、`PATH` に置く。

スキャナーは `PATH` 上の gitleaks を自動検出する。設定は不要。

## gitleaks を強制する（strict モード）

既定では gitleaks 未導入でもブロックせず、ベストエフォート検出に切り替えて冒頭に警告を出すだけ（ゼロ依存で動く利点を保つため）。
網羅性を担保したいリポジトリやチームでは、強制を opt-in できる：

- `python3 scripts/scan.py --require-gitleaks ...` を使う。
- または環境変数 `SCRUB_REQUIRE_GITLEAKS=1` を設定する（CI で一括有効化しやすい）。

どちらかが有効なとき、gitleaks が見つからなければスキャナーはエラー終了（exit `2`）し、スキャン自体を行わない。
これにより「gitleaks が入っている環境でしか `commit` させない」運用が可能になる。
内蔵の正規表現フォールバックは、gitleaks を入れられない環境のために既定では残してある。
