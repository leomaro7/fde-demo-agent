この一覧を作る過程で欠陥が 1 件出た。 CLAUDE.md は「push の前に pre-commit-scrubber を通す」と定めているのに、スキル本体が手元の個人領域にしか無かった。 企業リポジトリはテンプレートから .claude/ ごとコピーされるので、そちらには付いてこない——公開事故を防ぐ最も重いルールが環境依存になっていた。 同日にリポジトリへ入れて解消（skill が 5 本から 6 本になったのはこのため）。

それぞれが在る理由

ハーネスの原則は「まだ踏んでいない失敗は 1 つも入れない」。だから各部品には、それを生んだ事故が対応する。

部品いつ由来した失敗
new-demoメモを受け取った直後「答えてはいけないこと」を聞かずに作り、何でも答えるデモになった
aws-fact-checkAWS を書く前と、変えた後前身で API の形を 7 箇所すべて推測で外した。今日はモデル ID を呼ばずにコミットして 3 回続けて誤診した
verify-runbook手順書を書くとき前身で README を全部書いてから検証し、6 箇所の欠陥が出た
cleanup-check撤去後、数が合わないときUser Pool がドメインを持ったまま削除に失敗し、気づかず放置された
file-issue「次回にしましょう」と決めたとき調べた結果を残さず、次のセッションが同じ AWS を建てて測り直した
demo-qualityクライアントに見せる前拒む条件と探すのをやめる条件が繋がっておらず、山場が丸ごと無効化されていた
infra-reviewerデプロイ前グローバルに一意な名前を固定し、同一アカウントに 2 つ置けなくなった
pre-commit-scrubberpush の前共有物にクレデンシャルや取引先名が混ざる。2026-08-15 まで、このスキル自体がリポジトリの外にあった
session-context.pyセッション開始時消し忘れた Harness が課金され続けていることに気づかなかった

溜める先を間違えると、次のセッションが同じ調査を繰り返す

今日の棚卸し

ハーネス自身の原則に当てて、足りないもの 2 件と、古くなったもの 4 件を直した。

足した

変えたら、呼んで確かめる

モデル ID が一覧に出ることを確認しただけでコミットし、実際には呼べなかった。原因も測らずに断定して 2 回外した。参照ファイルは「再調査不要」として読まれるので、誤りを書くのが最も高くつく。

足した

自分が書いたものは自分でレビューできない

手順書を文脈のないサブエージェントに読ませたら 18 件出て、5 件は手が止まるものだった。cd が 1 つも書かれていないことに、書いた側は無意識に補完していて気づけない。

直した

決着済みを「未解決」と案内していた

要件書 7 章は 7.0 / 7.1 / 7.2 とも決着済み。「どこまでを IaC に載せるかは未決」も同じで、実際に外へ出したのはデモ用のユーザーだけ。

直した

ルールが手元の環境に依存していた

pre-commit-scrubber がリポジトリの外にあった。クローンした人には効かない。 実体を持たせて入れた（元は別のスキル集への symlink で、そのままだと他の環境で壊れる）。

直した

フックと権限の理由が失効していた

「構成がまだ決まっていない」が理由だったが、決まった。それでも置かないのは 同じ検査を new-demo が既にやっているから。許可リストの説明も実態と違っていた。

育て方

ルールが増える一方なら、それは失敗している。 速度を出すための基盤なので、ブレーキばかり増やすと目的から遠ざかる。足すときは加速側から足す。

起きたことどうするか
同じミスを 2 回ルールか skill にする。1 回目は運が悪かっただけかもしれない
仕様を推測して外したaws-facts.md に実測値を追記する
ルールが邪魔をしたルールを消す。 守れないルールを残すと全体が形骸化する
2 回守って問題が出ない消してよい。効いているか分からないルールを抱えない
判断に迷ったDECISIONS.md に理由ごと残す

構造を前提にするルールを書かない。 ディレクトリ名・スクリプト名・ファイル形式に依存する仕組みは、それが決まってから作る。間違った前提を強制する仕組みは、無いより悪い。

規模 — CLAUDE.md 177 行 / RUNBOOK.md 708 行 / DECISIONS.md 545 行 / REQUIREMENTS.md 432 行。skill は new-demo 649 行（参照 3 ファイル込み）、aws-fact-check 529 行（実測値の表込み）、verify-runbook 194 行、cleanup-check 153 行、file-issue 119 行。
